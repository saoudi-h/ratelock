# DOCS-PERF-01 — worklog (2026-10-27)

Goal: home page Lighthouse (prod mobile 65, desktop 81 reported; 65/96 measured here).

## Findings
- LCP element (hero text) was gated on JS: h1 `opacity:0` inline, description `gsap-prep` + delay.
- Hydration long tasks (~200 ms at 1x) were dominated by GSAP `fromTo` immediate renders: each read `getComputedStyle` after a write -> forced style recalcs (`_getComputedProperty` ~400 ms at 4x).
- Iconify fetched icons from api.iconify.design at runtime (10+ requests, late icons, CLS).
- Session replay `r.js` (45 KiB) loaded eagerly.
- Local static server inflates simulated LCP (no compression); use preview deployments to compare.

## Changes (apps/docs)
- Hero title, badge, CTAs, code panel, scroll cue, stats: CSS keyframes (`.hero-animate` in `app.css`), no GSAP entrance; stats chars are React-split spans.
- `lazyWhenIdle`: below-the-fold sections hydrate at first interaction (12 s fallback), one slot at a time.
- Iconify bundled by `scripts/generate-icons.ts` -> `src/generated/icons-{core,deferred}.ts`.
- `r.js` injected after load+idle; monospace font preloads dropped.

## Results (Vercel preview, median of 3, Lighthouse mobile/desktop)
- Before: 65 (LCP 5.3 s, TBT 530) / 96.
- After: ~90 (LCP 3.3-3.8 s simulated, TBT ~60) / 99. Docs page 95 / 100.
- One mobile run in three showed TBT 830 ms (timing of the deferred fallback); fallback raised from 8 s to 12 s.

## Next
- Remaining simulated LCP ~3.5 s is render-blocking CSS (268 KB, 39 KB gz, mostly Fumadocs + shadcn classes) + fonts; pruning unused `components/ui/*` or inlining critical CSS would help.
- Git: repo had `core.fsmonitor=true` returning stale status after big file ops; disabled locally (`git config core.fsmonitor false`).
