# Worklog — 2026-08-22 — BENCH-01

## What was done

Benchmarked Bun 1.4 native RedisClient against traditional clients through the existing `packages/bench` harness.

1. Extended `src/driver-compare.ts`: added a bun-native variant (auto-detected by our new `'bun'` driver, graceful SKIP under Node), parameterized per-variant duration via `BENCH_DRIVERS_DURATION_MS` (default 3000).
2. Added scripts: `bench:drivers` (Node/tsx) and `bench:drivers:bun`.
3. Environment hiccups resolved: leftover BUN-02 test container occupied port 6380; first bench compose start produced a container with NO published ports — fixed with `docker compose down && up -d --force-recreate redis-bench`.
4. Ran Node baseline + two Bun runs (5s/variant each) against the same Dockerized Redis 8-alpine.

## Results

| Variant | ops/s (runs) | p50 | p95 | p99 |
|---|---|---|---|---|
| **bun native** | **76,393 / 75,572** | **122–124μs** | 185–187μs | 219μs |
| ioredis (Bun) | 74,345 / 67,333 | 123–142μs | ~191–201μs | 234μs |
| node-redis (Node) | 54,560 / 49,821 | 168μs | 245μs | 299μs |
| node-redis (Bun) | 45,616 / 50,177 | 185–204μs | ~254–279μs | 330μs |
| ioredis (Node) | 45,561 / 47,048 | 161μs | 474μs | 619μs |

Full report saved to `packages/bench/results/driver-compare-bun-native.md`.

Key findings:
- Bun native wins ALL metrics (+40% vs best Node combo, tightest tails). Stable ordering across runs (<2% variance).
- node-redis DEGRADES under Bun (−9%); ioredis improves dramatically under Bun but still trails native.
- Answer to the maintainer's question: yes, the Bun native implementation genuinely surpasses bun+traditional-client combinations for this workload.

## Key decisions and why

- Benchmarked via instance-passthrough mode (same shape as other drivers) for apples-to-apples comparison.
- Kept harness conventions (skip-on-missing-dep, console table) rather than introducing new framework code.
- [BUN-03] stays PARKED: this evidence is Redis-only and does not address the unified-API concern for Postgres.
