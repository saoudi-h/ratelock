## Hard-won NestJS findings (all encoded in code comments + tests)

1. **esbuild/vitest do not emit `design:paramtypes`** even with `experimentalDecorators` → implicit type-based DI breaks under test. Fix: explicit `@Inject(...)` on EVERY constructor param (including `Reflector`).
2. **`APP_GUARD` with `useExisting` fails** while the scanner processes importer modules of a dynamic global module ("cannot export provider that is not part of the module"). Fix: `useClass` — the guard is stateless beyond the shared memoized resolver, duplicate instances harmless.
3. **String-token exports from a global dynamic module** propagate into importer modules and fail export validation ("cannot export RATELOCK_OPTIONS..."). Fix: export only the guard class; tokens stay internal.
4. **vitest/esbuild ignores the tsconfig `experimentalDecorators` flag** in some combinations → decorators compile as TC39 standard, silently breaking `SetMetadata`/`Reflector` reads. Fix: pin `esbuild.tsconfigRaw.compilerOptions.experimentalDecorators = true` in vitest.config.ts. (Initially misdiagnosed as a decorator-arg-shape problem; reverted a dual-shape decorator experiment before finding the config fix.)
5. Debugging pattern that worked: bisect providers array + minimal repro test file inside the package.
