# HOME-FIX-03 — Hide the 3D hero illustration on mobile

Outcome: After two unsuccessful animation-level fixes, the maintainer chose to hide the illustration below 768px rather than ship a broken visual. Confirmed stable on a physical Samsung S23 in both Chrome and Firefox. Desktop keeps the original scene unchanged.

Decisions:
- Elimination flags (`?hero=...`) showed `off` (no GSAP) and `nosim` (entrance only) stable, but `noloops`, `nochart`, `noentry` and `nofilter` all still flickered. A `flat` mode neutralizing 3D transforms and filters while GSAP kept running was fully stable.
- Root cause is non-deterministic layer compositing of the `preserve-3d` stack on mobile GPUs: missing objects varied between reloads, the page worked on a 15-year-old desktop, and a powerful S23 failed in both browsers. Not a power issue, not one specific tween.
- Used `hidden md:block` on the illustration container plus an early return in `useGSAP` when `matchMedia('(min-width: 768px)')` does not match, so no animation work runs for an invisible element.
- All temporary debug flags and CSS were removed before commit.

Validation:
- `pnpm build` -> 15/15, 70 pages, no "Error in render".
- `pnpm lint` / `pnpm typecheck` -> 16/16 clean; 231 tests passed; `oxfmt --check` clean.
- Maintainer verified on an S23 via the LAN dev server: no flicker, page otherwise normal.

Open: A 2D-equivalent mobile design could restore the visual later; do not re-enable the 3D scene below 768px without solving layer composition first.
