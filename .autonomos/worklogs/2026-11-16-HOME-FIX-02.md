# HOME-FIX-02 — Fix mobile hero flicker: root lagSmoothing override, GPU-heavy filter pulse, ResizeObserver loop

Outcome: HOME-FIX-01 was neutralized at runtime: `LenisGsapBridge` called `gsap.ticker.lagSmoothing(0)` after `registerGsap()`, so slow mobile frames advanced every tween by the full delta and produced random phase jumps on both Chrome and Firefox phones. Fixed the root override, replaced the animated drop-shadow/oklch pulse with an opacity pulse, and removed the self-feeding ResizeObserver. Build, lint, typecheck and 231 tests pass; device verification is still required.

Decisions:
- Set `lagSmoothing(500, 33)` in `__root.tsx` as well as `gsap.ts`: the ticker is global, so all call sites must agree; GSAP maps `0` to `Infinity` and disables lag protection entirely.
- Animate `opacity` on the check icons instead of `filter: drop-shadow(oklch(from ...))` with random stagger: the latter re-resolves relative colors and re-rasterizes two shadows per frame on a 3D layer, and out-of-phase yoyo matches the reported random light/dark popping.
- Replaced the ResizeObserver on the scaled container with a `window` resize listener and dropped the `height 0.15s` transition: the observer refired on every frame of its own height change and forced synchronous layout via `getBoundingClientRect`.
- Kept one repeating chart tween instead of the recursive `onComplete` from HOME-FIX-01: each cycle retained two completed tweens in the `useGSAP` context, adding GC pressure on memory-constrained phones.

Validation:
- `pnpm build` -> 15/15, 70 pages prerendered, no "Error in render".
- `pnpm lint` / `pnpm typecheck` -> 16/16 clean.
- `pnpm exec vitest run` -> 28 files, 231 tests passed.
- `oxfmt --check` on both edited files -> clean.
- grep: only `lagSmoothing(500, 33)` remains in apps/docs (both call sites consistent).
