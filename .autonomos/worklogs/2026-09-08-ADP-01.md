# ADP-01 — Upstash Redis adapter

## What was done

- Added the technical implementation of `@ratelock/upstash` for the four existing strategies: fixed window, sliding window, token bucket, and individual fixed window.
- Extracted the Lua strategy execution and resilience decoration into the private, transport-neutral `@ratelock/redis-common` package.
- Kept `@ratelock/redis` behavior unchanged at its public API while routing it through the shared strategy layer.
- Added an Upstash client adapter using `SCRIPT LOAD`, `EVALSHA`, and ordered REST pipelines. `destroy()` is intentionally a no-op because the official client is HTTP-based.
- Added fast Upstash-shaped unit fakes and a reproducible local HTTP integration suite. It starts Redis plus the Serverless Redis HTTP bridge recommended by Upstash; the real-service suite remains opt-in with `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`.
- Added a patch changeset for the new package, CI publint coverage, and scoped architecture guidance.
- Added the package README, MIT license, Fumadocs engine guide, runtime/installation guidance, framework recipes, package README references, and homepage engine cards.
- Added a compile-time compatibility guard for `@upstash/redis/cloudflare` and documented the provider-specific Cloudflare entry point.
- Added a separate opt-in Upstash HTTP characterization benchmark. It measures cold versus warm calls, SDK `fetch` request counts, HTTP statuses (including `429`), transport errors, and `checkBatch` pipeline efficiency without mixing those numbers into the local Redis/Postgres tables.

## Key decisions

- The public API accepts an existing `@upstash/redis` client instead of credentials or a URL. This keeps credential handling in the official client and supports Node, serverless, and provider-specific Edge entry points.
- The shared layer exposes only the script surface needed by the strategies, so the Upstash bundle does not import Node Redis drivers or runtime globals.
- `checkBatch` uses Upstash's ordered pipeline but does not claim cross-key transactionality; each Lua invocation remains the atomic unit.
- The real Upstash test uses a latency-tolerant fixed-window scenario. The generic 500 ms contract is retained for local/unit tests because sequential HTTP calls can legitimately outlive that window.
