# DOCS-01 - Fix home ScrollTrigger crash on browser back

## What was done

- Reproduced the reported failure with Firefox 154 through WebDriver BiDi at a 1477x831 viewport, equivalent to a FullHD viewport narrowed by 130% zoom and developer tools.
- Confirmed that the uncommitted IntersectionObserver and global route refresh attempt still failed on browser back with `TypeError: can't access property "end", curTrigger is undefined`.
- Reworked the invalid child-tween ScrollTriggers in `SimulationSection`, but did not treat that local fix as sufficient after the maintainer reproduced the same failure in `useSplitReveal`.
- Identified the shared failure: restoring a deep scroll position initializes many `once` triggers beyond their end while SplitText `autoSplit` can retain old animations if `onSplit` does not return them. Trigger removal then mutates GSAP's registry during its internal refresh iteration.
- Enabled `ScrollTrigger.config({ limitCallbacks: true })`, the GSAP setting intended for pages initialized at an already-advanced scroll position.
- Returned managed animations from every active SplitText `autoSplit` callback and enabled dependency cleanup in `useSplitReveal`.
- Separated the Explore CTA root and title tweens so SplitText can revert its title animation independently on each resplit.
- Reworked the section entrance so one ScrollTrigger owns the parent timeline and its two child tweens contain no ScrollTrigger configuration.
- Kept IntersectionObserver for lazy simulation loading and added an immediate reveal when restored scroll has already passed the section.
- Removed the experimental global route refresh provider and fixed replay registration cleanup in `SimulationSection`.

## Key decisions

- Used `limitCallbacks` instead of removing every `once` option. The default entrance behavior remains intact during normal scrolling, while skipped triggers no longer run callback and self-kill logic during deep-scroll restoration.
- Returned each `autoSplit` animation because SplitText uses that return value to revert the old tween and its ScrollTrigger before re-splitting on font or width changes.
- Used one timeline-level ScrollTrigger in `SimulationSection` because GSAP does not support giving a child tween both a parent timeline playhead and its own ScrollTrigger playhead.
- Did not add `ScrollTrigger.killAll()`. `useGSAP` already owns route-local trigger cleanup, while a global kill would also destroy valid triggers and could race with newly mounted home effects.
- Did not retain route-wide delayed refreshes. They added refresh windows but did not fix the trigger ownership defect.
- No changeset was added because this is a private docs application fix, not a published package change.

## Verification

- Baseline: exact Firefox flow reproduced the Next.js error boundary and GSAP `curTrigger` exception.
- The maintainer then reproduced the failure at `use-split-reveal.ts:69`, proving the first local fix was incomplete.
- Final fixed flow: the maintainer confirmed the exact Firefox 130% zoom and open-console reproduction no longer fails.
- Automated stress flow: ten home -> NestJS docs -> browser back cycles, alternating viewport widths and dispatching `document.fonts.loadingdone` before every navigation, completed without JavaScript errors or the error boundary.
