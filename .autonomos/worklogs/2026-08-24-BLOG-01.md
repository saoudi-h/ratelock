## Key decisions and why
- **Reuse Fumadocs primitives vs new framework:** Fumadocs official site is itself a docs+blog app using `defineCollections` + `loader`; copying that pattern costs <30 LOC and keeps `.source` generation, types, and MDX handling unified. No new CMS or external service.
- **defineCollections + toFumadocsSource vs defineDocs:** `defineDocs` bundles docs+meta; blog is a flat `doc` collection so `defineCollections` + `toFumadocsSource(blog, [])` is the correct runtime type (verified via `runtime/server.d.ts`: `server.doc` returns `DocCollectionEntry[]`, not `DocsCollectionEntry` with `.toFumadocsSource`). Attempted `blog.toFumadocsSource()` failed typecheck; switch to `toFumadocsSource(blog, [])` fixed it.
- **z.coerce.date() for date:** Allows frontmatter dates as `YYYY-MM-DD` strings while normalizing to `Date` objects for sorting and RSS. Avoids `z.iso.date()`/`z.string().date()` fragility across zod 4 variants.
- **No extra dep for RSS:** `feed` npm not added; manual XML keeps bundle small and avoids async build dep. Escaping handled via `escapeXml`.
- **Keep default MDX compiler:** Official blog uses `satteri`; RateLock docs uses default `mdx` with `remarkSteps`. Blog stays on default for consistency; `body`/`toc` available synchronously (`page.data.body`) without `load()` dance.
- **9 stubs, not full long-form:** Provides durable URLs, metadata, navigation, and internal linking scaffold for SEO; full editorial depth can be iterated per article without blocking the surface. Each stub still has >200 words, code snippet, and 3-4 internal links for crawlability.
- **Sitemap includes blog:** Ensures search engines discover posts without waiting for external links; RSS provides distribution hook for X/dev.to.
