## What was done

Designed then implemented `@ratelock/hono`, first framework integration.

### Design decisions locked with maintainer before coding
- Architecture A: one package per framework, no shared abstraction until rule-of-three ([INT-04] registered).
- Limiter injection: instance OR lazy factory — factory memoized singleton, initialized on FIRST matched request only (maintainer's edge/cold-start concern addressed natively, not via later helper).
- Headers: both families by default (`RateLimit-*` RFC 9331 + legacy `X-RateLimit-*`), configurable `'both' | 'rfc' | 'legacy' | false`; GitHub-style transition practice.
- Identifier: runtime-provided remote address default (Node socket / Bun requestIP / Deno remoteAddr), shared 'anonymous' bucket fallback, keyGenerator override; proxy/spoofing guidance in docs.

### Implementation notes / gotchas discovered
- Hono has NO universal getConnInfo — only adapter-specific implementations ('hono/conninfo' exports just the type). Solved by probing common `c.env` shapes (node-server incoming socket, Bun requestIP, Deno remoteAddr) with optional chaining.
- Hono requires `ContentfulStatusCode` for response status → option typed accordingly (better DX too).
- Token bucket results lack window `remaining`: projection maps floor(tokens) → Remaining, refillTime/reset/windowEnd (epoch-vs-duration heuristic at 1e12 ms) → seconds for Reset/Retry-After.
- Fumadocs requires `title` frontmatter on MDX pages (build caught it).
- tsconfig include needed tests/ + vitest.config.ts for the ESLint project service.
- cspell: added "Contentful", "spoofable" to wordlist.
