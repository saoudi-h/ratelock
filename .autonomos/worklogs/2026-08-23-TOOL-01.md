## Key facts

- tsdown dts works with typescript@7.0.2 — no blocker found; native tsc typecheck of whole monorepo ≈ 4s.
- oxlint nested config discovery: nearest `oxlint.config.ts` wins per file, configs are NOT merged; explicit `--config` disables lookup.
- oxfmt supports JS/TS/JSON/CSS natively + Prettier-backed MD/MDX/YAML; respects `.gitignore` and supports `ignorePatterns` (used for generated `CHANGELOG.md`).
- **Incompatibility found:** `better-tailwindcss/enforce-consistent-line-wrapping` cannot coexist with oxfmt. Root cause chain: (1) oxfmt's JSX printing differs from Prettier's (attribute-on-own-line for multiline values, ternary breaking), (2) the rule is indentation-sensitive so oxfmt's reshaping invalidates its expectations, (3) its autofix splits short template literals into multiline ones, which changes how oxfmt prints the surrounding expression → same 25 docs files dirty on every format↔lint round-trip (verified over multiple passes). Tuning `{ preferSingleLine: true, printWidth: 100 }` reduced it to 2 files but the last blocker is semantic: the plugin measures printWidth WITHOUT JSX indentation, oxfmt WITH it — boundary-length lists oscillate forever. Rule disabled in docs; note the committed prettier-era code triggered 0 warnings (the old pair was genuinely stable together). All other better-tailwindcss rules (order/canonical/duplicates/unknown) converge with oxfmt and stay active.
- oxlint honors legacy `// eslint-disable-next-line <rule>` comments; all stale ones removed (rules not active under oxlint presets), `not-prose` moved into better-tailwindcss settings.ignore.
- express/fastify "major" updates in outdated output were the npm aliases (`express4`, `fastify4`) — dual-test legs intact, no action needed.
