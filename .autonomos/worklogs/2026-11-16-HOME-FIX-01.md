# HOME-FIX-01 — Stabilize mobile home: hero illustration flicker + transient horizontal overflow

Outcome: The hero illustration no longer receives touch-synthesized tilt input, the traffic simulation updates once per cycle, and the document clips horizontal overflow so deferred GSAP card entrances cannot create a mobile scrollbar. Build, lint, typecheck and all 231 tests pass; a 390px viewport check shows document scrollWidth equal to clientWidth.

Decisions:
- Gated the 3D tilt on `pointerType === 'mouse'`: Chrome/Android synthesizes `mousemove` from touch and scroll, which was continuously rewriting `--tilt-z` on a `preserve-3d` subtree with ~24 filtered layers.
- Replaced `repeat: -1` + `onRepeat` with a recursive `onComplete` tween and added `overwrite: true` to the counter tween: a slow mobile frame can no longer burst several simulation updates and rewrite chart `d` / `textContent` in one tick.
- Restored GSAP default lag smoothing (it was `lagSmoothing(0)`): disabling it let long frames advance tweens by the full delta.
- Split the measurement effect from the pointer-listener effect so a `scale` change no longer re-registers the `ResizeObserver` and section listeners.
- Used `overflow-x: clip` on `html`/`body` instead of hiding each animated section: `clip` does not create a scroll container, so Lenis scrolling and sticky elements are preserved.

Validation:
- `pnpm build` → 15/15 tasks, 70 pages prerendered, no "Error in render".
- `pnpm lint` → 16/16 clean; `pnpm typecheck` → 16/16 clean.
- `pnpm exec vitest run` → 28 files, 231 tests passed.
- `oxfmt --check` on the three edited files → clean.
- Preview at 390x844 → `scrollWidth === clientWidth` (375px), computed `overflow-x: clip`.

Open: Physical-phone confirmation on Chrome/Android remains with the maintainer; GPU layer-composition flicker is not reproducible in a desktop headless browser.
